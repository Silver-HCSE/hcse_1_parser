# Hallmarks of cancer search engine part 1

## Overview

This is the first part of a multi-part project to build a search engine for cancer publications entirely from the ground up in rust. Rust dependencies are allowed, but we will not use any pre-trained models or similar. Instead, we will use some classical numerics and build all the parts ourselves as an exercise in real-world problem solving. 

## This module

This repository contains the code of the parser (or mainly the downloader). The parser reads the publicly available data of the PubMed online archive to generate a base dataset for further work. In PubMed, there is much more data than what we need for this project. This tool downloads the compressed data, checks the download for integrity, decompresses it, filters the contained artices for abstracts mentioning cancer and then writes a subset of the data (title, abstract, id) to an output file.

Please be aware, that this tool processes a lot of data. The PubMed Baseline contains over one thousand files (in 2025) and each can be as large as 100MB compressed - decompressed they can be over 1GB each. By default, this tool runs 10 processes to parallelize the work. You can set the number of processes as an input argument.

As a reference: With Gigabit internet, an AMD Ryzen 9 7900X and using 10 processes, this tool runs for around 7 hours.

This tool does not slice the work into first doing all the downloads, then all the decompression, then all the parsing etc. because it require storing all the unfiltered (but compressed) PubMed data for some time locally and that would likely  require somewhere in the area of 100GB of storage. By directly processing the data after download and deleting everything we don't need as quickly as possible, we can get this value down to (Number of Processes) x (Max Size of Data Per Process = roughly 1GB).

Two additional points: 
- The tool can restart, so re-running it, will pick up output files that are already present and not re-attempt those.
- This tool only has to run once. Once you have all the 'results_pubmed25nXXXX.xml.json' files somewhere, you don't have to reload and reprocess the data.
